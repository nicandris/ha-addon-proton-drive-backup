# v0.5.0 (planned) — appear in Home Assistant's Backups → "Locations"

**Status: NOT STARTED — design captured for later. Deferred (big change).**

Goal: make Proton Drive show up as a native backup **Location** in HA
(Settings → System → Backups → Locations), alongside "This system" and
"Home Assistant Cloud backup", so HA writes backups to Proton directly and can
restore from it.

## Why this needs a NEW component (the crux)

The Locations list is populated **only by integrations** that implement HA's
**Backup Agent platform**. An **add-on cannot register a Location** — confirmed
against `home-assistant/core`:
- the `backup` integration iterates loaded **integrations'** `backup` platforms;
- the Supervisor (`hassio` integration) only auto-provides agents for **local
  storage** and **network mounts** (CIFS/NFS) — not arbitrary CLI targets.

Proton access here is the official **`proton-drive` CLI binary**, which **cannot
run inside HA Core's Python sandbox** (the reason the original pure-Python design
was abandoned). So the design is: a **companion custom integration** (the backup
agent, in HA Core) that **bridges over HTTP to this add-on** (which runs the CLI).
This Core-integration → companion-add-on pattern is exactly how Music Assistant,
Wyoming, and Matter work.

## Architecture

```
HA backup manager
      │  (streams AsyncIterator[bytes])
      ▼
custom_components/proton_drive  (NEW — Python, HACS)
   backup.py: BackupAgent  ── chunked HTTP ──►  this add-on's NEW internal API
   config_flow.py: host/port + shared token                 │
                                                             ▼  stage temp file
                                                    proton-drive upload/download/list/delete
                                                             │
                                                             ▼
                                                        Proton Drive
```

## Part 1 — new custom integration `proton_drive`

Files: `custom_components/proton_drive/{manifest.json, __init__.py, config_flow.py, backup.py, const.py}`.

- **`backup.py`** exposes:
  - `async def async_get_backup_agents(hass) -> list[BackupAgent]`
  - `@callback def async_register_backup_agents_listener(hass, *, listener, **kwargs)`
  - `class ProtonDriveBackupAgent(BackupAgent)` implementing (all streamed where noted):
    - `async_list_backups() -> list[AgentBackup]`
    - `async_get_backup(backup_id) -> AgentBackup`
    - `async_upload_backup(*, open_stream, backup, **kwargs)` — await `open_stream()` → `AsyncIterator[bytes]`, relay chunked to the add-on
    - `async_download_backup(backup_id) -> AsyncIterator[bytes]`
    - `async_delete_backup(backup_id)`
    - `domain`, `unique_id`, `name`, `agent_id = f"{domain}.{unique_id}"`
  - Raise `BackupAgentError` / `BackupNotFound` on failure.
- **Config flow**: add-on host + port + bearer token (defaults to the add-on
  hostname; see auth below). Degrade gracefully with timeouts if the add-on is down.
- Distributed via **HACS custom repository** (category: Integration).

## Part 2 — new internal HTTP API on the add-on

Separate from the ingress UI. Endpoints (bearer-token auth):
- `POST /agent/upload/<backup_id>` — receive a **streamed** request body → write to
  `<staging>/<backup_id>.tar` → `proton-drive upload` → delete temp.
- `GET  /agent/download/<backup_id>` — `proton-drive download` to temp → stream back
  chunked → delete temp.
- `GET  /agent/list`, `GET /agent/get/<id>`, `DELETE /agent/delete/<id>` — JSON,
  shell out to the CLI (reuse `protonCli` + the existing name↔slug/`AgentBackup`
  mapping; HA `backup_id` ↔ our remote `(slug).tar`).
- New config option `api_token` (bearer). Expose an **internal-only** port in
  `config.yaml` `ports:` (reachable by HA Core over the Supervisor Docker network,
  **not** mapped to the LAN). Reach from the integration by the add-on hostname
  `{repo}_{slug}` (dashes) or a user-entered host:port.

## Decisions (accepted by user)

- Internal-only port + **add-on-owned bearer token** (NOT `SUPERVISOR_TOKEN`,
  which is add-on→Core only). Minimal network surface.
- **Two-step install**: add-on repo (existing) + integration via HACS. No single
  install registers both (can live in one GitHub repo, still two sources).
- Pin to a tested HA version — the backup-agent API is **new (2025.1/2.2) and still
  evolving**; expect to track `backup/agent.py` changes.

## Gotchas / must-handle

- **Stream end-to-end** (chunked both hops) or multi-GB backups OOM. Add-on temp
  staging needs disk.
- Agents are **bidirectional** — implementing download correctly = restore-from-Proton
  works; if download is broken, restore silently won't.
- HA backups arrive **already AES-encrypted** client-side (agent relays an opaque tar;
  can't inspect/dedupe contents).
- Add-on stopped → Location errors on use; `async_get_backup_agents` should still
  return the agent so it shows, but ops fail until it's up.
